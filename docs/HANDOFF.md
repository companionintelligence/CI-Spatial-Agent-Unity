# Handoff — CI Spatial Companion (Unity)

_State of `main` after PR #18, together with the build-hygiene, runtime-configuration, CI and licensing work integrated for the first release candidate, plus the CI described in [CI.md](CI.md). This replaces the 2026-07-18 handoff for the MR scene rig, which is done. Read this first, then [ARCHITECTURE.md](ARCHITECTURE.md), [BUILD.md](BUILD.md) and [CI.md](CI.md)._

## Where things stand

- **Unity 6.3 LTS** (`6000.3.19f1`), URP, OpenXR-first, **one APK per headset** (Quest 3 and Pico from the same code; see BUILD.md). Repo `companionintelligence/CI-Spatial-Agent-Unity`. The first commit of the rebuild reached `main` through PR #14, and the MR rig, passthrough, per-headset packaging and lip-sync through PR #18.
- **MR rig is done.** `Assets/XRScan/App/Scenes/XRScan_Main.unity` is generated by `MRSceneBuilder` (menu **XRScan → Scene → Rebuild MR rig**). It contains an AR Session, an XR Origin with floor tracking, and a transparent AR camera carrying `TrackedPoseDriver`, `ARCameraManager`, `ARCameraBackground` and `ARFoundationCameraProvider`. The avatar stands 1.8 m in front of the user, facing them. Change the scene through the builder, not by editing its YAML.
- **Passthrough is visible.** HDR is off on both URP pipeline assets, and the AR camera renders LDR with no post-processing. An HDR intermediate made the eye buffer opaque, so the headset showed black.
- **Controller input is wired.** `XRInputController`: trigger → `AppBootstrap.Scan()` (place a pin), grip → `AppBootstrap.ToggleListen()` (voice Q&A). Both hands are bound; Space / L work in the Editor.
- **Per-headset packaging.** The project is Quest-first: the PICO SDK is not in `Packages/manifest.json`. Each build first changes the package set for its APK (`XRScanBuildPackages`: the Pico build adds the PICO SDK from a pinned commit, both builds remove MCP for Unity), builds after the script reload and then restores it. Each APK also leaves out the other vendor's native libraries and permissions (`XRScanNativeLibExcluder`, `XRScanManifestPostProcessor`).
- **Lip-sync tuned.** Viseme weights are capped at 100 %, visemes blend by phoneme ratio with smoothing, and `MockTts` sweeps vowel formants so the mock mouth moves through shapes.
- **Avatar.** The scene avatar is the CI-owned `CI_Companion.glb`, generated by `tools/avatar/build_ci_companion.py`. The Ready Player Me avatars and SDK were removed.
- **Tests.** There are 125: 122 EditMode (13 scanning, 6 avatar-model, 1 licence-inventory, 85 configuration and 17 release-signing tests) and 3 PlayMode scanning-pipeline tests. CI runs both suites on every pull request.
- **Quest 3, device-verified (2026-07-18).** The APK builds, installs and launches with 0 Unity errors. The Meta OpenXR session synchronizes, and passthrough composites with the avatar visible at about 72 fps.
- **Pico.** The APK builds and its manifest checks out with `aapt2`, but it has not been run on a device yet.
- **Real backends.** `XRScan_Main` has `useMocks` off: `CompanionConfig` points it at the `ServerConfig` / `LlmConfig` / `VoiceConfig` assets in `Assets/XRScan/Config`, and no server is configured out of the box. The mock wiring lives in `XRScan_Dev`, which is not in the build.

## Environment and commands

- **Editor:** Unity `6000.3.19f1` from Unity Hub, with Android Build Support (OpenJDK, SDK and NDK modules).
- **adb:** `<editor>/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb`, with a Quest 3 connected over USB and authorized.
  - Install: `adb install -r -g Builds/CISpatialCompanion-Quest.apk`
  - Launch: `adb shell am start -n com.companionintelligence.xrscan/com.unity3d.player.UnityPlayerGameActivity` (the APK's only activity since the switch to GameActivity; `UnityPlayerActivity` is no longer in it)
  - Logs: `adb logcat -s Unity:*` (our `Debug.Log` lines show as `Unity :`). Headset frame: `adb exec-out screencap -p > frame.png`.
  - Quest shows a **"Controllers Required"** system dialog before launching (the app has no hand tracking). Wake the Touch controllers or dismiss it, otherwise the app process never starts.
- **aapt2:** `<editor>/Data/PlaybackEngines/AndroidPlayer/SDK/build-tools/36.0.0/aapt2`. See [BUILD.md](BUILD.md#verifying-a-build) for what a correct APK contains.
- **Builds:** menu **XRScan → Build → Quest 3 / Pico**, or headless `Unity.exe -batchmode -projectPath . -buildTarget Android -executeMethod XRScan.EditorTools.XRScanBuilder.BuildQuest` without `-quit` (the builder takes MCP for Unity out of the project for the build, adds the PICO SDK for a Pico build, restores the package set and exits by itself; see [BUILD.md](BUILD.md)).
- **Unity MCP** (`com.coplaydev.unity-mcp`, `mcp__UnityMCP__*` tools): pinned to v10.3.0; `XRScanBuilder` removes it from the project for the length of every player build, so the bridge drops while a build runs and returns when the package is restored. Set `UNITY_MCP_DISABLE_TELEMETRY=1` to opt out of its editor telemetry. The bridge exists only while the Editor is open on the project. Its `execute_code` compiles C# 6 through CodeDom, so there are no local functions and no `out var`; use `System.Action<>` lambdas and fully qualified type names. Blocked APIs such as `AssetDatabase.DeleteAsset` need `safety_checks: false`.

## Gotchas

- **Validate tests in batch mode**, not just in the Editor; CI runs batch mode. A freshly created collider is not in the physics scene after one frame, so call `Physics.SyncTransforms()` and `yield return new WaitForFixedUpdate()` before raycasting against it.
- **A newly written `.cs` can end up in no assembly.** There is no compile error, and the test runner silently does not find it. Delete it (`AssetDatabase.DeleteAsset`), recreate it under a new file name and request a script compilation. Confirm with reflection over the assembly's `GetTypes()`.
- **Build only through `XRScanBuilder`** (menu, `-executeMethod` or CI). Quest and PICO OpenXR features cannot both be on, and a plain File → Build or a Build Profile does not switch them. The committed OpenXR settings are the Quest state (Meta features on except the unused ones `XRScanBuilder` keeps off; no PICO features in the list, since the PICO SDK is installed only during a Pico build) and the committed Android define is `XRSCAN_QUEST`; `XRScanBuilder` sets both again on every build. **XRScan → Build → Dump OpenXR features** lists the current state.
- **Let `com.unity.xr.meta-openxr` own the Meta permissions.** Adding them in `XRScanManifestPostProcessor` leaked them into the Pico APK.
- **`PluginImporter` platform flags do not work for native libraries inside read-only packages.** Strip them at Gradle packaging time, as `XRScanNativeLibExcluder` does.
- **Under Vulkan, the URP renderers need `ARCommandBufferSupportRendererFeature`**, or `ARSession.Update` throws every frame.
- **Keep HDR off** on the URP pipeline assets, or passthrough turns black.
- **The editor's Android OpenJDK module can be missing** even with the SDK and NDK present ("Failed to update Android SDK package list" / "JAVA_HOME invalid"). Install it with `"Unity Hub.exe" -- --headless install-modules --version 6000.3.19f1 -m "android-open-jdk-17.0.18+8"` (the exact versioned module id).
