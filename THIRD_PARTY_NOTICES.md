### 1.3 Android libraries added by the Gradle build

Unity's Android build generates a Gradle project and adds libraries to it that no Unity package declares, so they are not in `Packages/packages-lock.json`. Because `XRScanBuilder` selects the GameActivity application entry point, Unity's generated `unityLibrary/build.gradle` declares `androidx.appcompat:appcompat:1.6.1`, `androidx.core:core:1.9.0`, `androidx.constraintlayout:constraintlayout:2.1.4` and `androidx.games:games-activity:4.4.0`, and Gradle resolves them and their dependencies from Google Maven and Maven Central. The Maven rows below are the complete list that the Android Gradle plugin recorded for the rc1 Quest APK (`launcher/build/outputs/sdk-dependencies/release/sdkDependencies.txt` in the generated project); the Pico APK has the same `META-INF/*.version` files and the same classes from these libraries, plus Gson from the PICO SDK. Minification is off, so every class of these libraries is in `classes.dex`, and 329 of each APK's 335 `res/` files are their resources (259 of them AppCompat's `abc_*` files). Every Maven artifact here declares the Apache License 2.0 in its POM (`listenablefuture` through its parent POM) and none contains a `NOTICE` file; their notices and the licence text are in §5.2.

GameActivity also brings native code. `libgame.so` is compiled during the Gradle build from Unity's GameActivity glue code (Unity runtime, §1.1) and the static library in `androidx.games:games-activity`, and it links the NDK's C++ runtime `libc++_shared.so`, which is packaged for that reason: no other library in either APK needs it.

## 6. How this was verified

- **Licences** were read from each package's `LICENSE.md` / `Third Party Notices.md` at the locked versions (the copies Unity imports into `Library/PackageCache`), from the licence headers of the third-party source files inside the shipped packages' runtime folders (which is how webgl-noise, xxHash in Collections, SMAA, FidelityFX FSR 1, ACES, Clipper, the MIT-licensed grass shaders and Burst's float formatter were found; their packages' notices files omit them. Shader-library files are listed when a shader in the build report includes them, e.g. FSR 1 but not the unused CAS, LPM and STP files), from the strings of the shipped native libraries (JsonCpp in `libopenxr_loader.so`) and, for git packages, from the upstream repository at the pinned commit (links above). The Ready Player Me shutdown date is from the PocketGamer.biz report linked in §3.
- **Android libraries** (§1.3): the list is the Android Gradle plugin's resolved runtime classpath for the rc1 Quest APK (`sdkDependencies.txt`: 47 Maven artifacts, plus the local `openxr_loader` and `unityandroidpermissions` AARs that §1.1 covers); the 30 `META-INF/*.version` files in each APK carry the same versions. Licences were read from each artifact's POM in the Gradle cache the build used (all declare the Apache License 2.0; `com.google.guava:listenablefuture` through its parent `guava-parent` 26.0-android), and the POMs name The Android Open Source Project and JetBrains as developers. None of the AARs and JARs, nor PICO's `gson-2.10.1.jar`, contains a `NOTICE` or `LICENSE` entry; GameActivity's copyright lines are from the headers in its AAR's `prefab` folder. `libc++_shared.so` (1,292,904 bytes in both APKs) is byte for byte the NDK r27c's `sysroot/usr/lib/aarch64-linux-android/libc++_shared.so` (1,794,776 bytes) after `llvm-strip --strip-unneeded`; it contains libc++abi (`__cxa_*` exports) and libunwind (its error messages), its licence is in the NDK's `NOTICE.toolchain`, and `libgame.so` is the only library that lists it as `NEEDED`. `libgame.so` (152,576 bytes, identical in both APKs) contains GameActivity's and GameTextInput's native code.
- **Avatar provenance**: the glTF JSON `asset` block and `extras` of every GLB were inspected. `CI_Brad.glb` and `LiamCES.glb` declared `"generator": "Ready Player Me"`, `"copyright": "Ready Player Me"`; `CI_Companion.glb` declares the Companion Intelligence copyright and its scene `extras` name the generator script and licence. `AvatarModelTests` (EditMode) fails if any GLB in `Assets/XRScan/Avatar/Models` lacks a copyright or names Ready Player Me.
- **APK contents**: `python tools/apk/scan_apk.py <apk> --target quest|pico` decompresses every file in an APK (managed metadata, native libraries, Dex, manifest and Unity's serialized data: scenes, `Resources`, settings) and searches it for names only the PICO SDK, MCP for Unity, Ready Player Me or Visual Scripting contain. Unity's build report ("Used Assets and files from the Resources folder" in the Editor log) lists every asset a build packed.
